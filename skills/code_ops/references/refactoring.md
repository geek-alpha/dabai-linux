# 重构决策准则（Fowler《重构》浓缩）

改代码前先过一遍，防止把重构做成重写、把清理做成隐藏功能变更。

## 何时用
改现有代码、准备功能/修 bug、清理债务、降低结构摩擦，且不打算改变可观察行为时。

## 首要纠偏
重构是**保持行为不变**的设计工作，小步走。不要把清理变成重写、隐藏功能变更或投机式架构。

## 决策规则
- **保持可观察行为不变**：行为变更与结构变更隔离，绝不把功能/迁移/重设计伪装成清理。
- **小步、可回退、可构建、可测试、可评审**：补丁大到无法局部推理就拆分。
- **先建安全网**：行为不清的用特征化测试（characterization tests）；测试更新与预期行为对齐；绝不删失败测试来"完成清理"。
- **围绕功能做预备/收尾重构**：先找出让改动别扭的结构，重塑局部，再做行为变更，最后清掉引入的债。
- **只重构当前阻塞的坏味道**，不是见一个清一个：重复、长函数、长参数列表、全局变量、发散式变化、霰弹式修改、依恋情结、基本类型偏执、重复条件、临时字段、中间人、投机性泛化。
- **优先最简单的命名动作**：改名、提取、内联、移动、拆分含义、引入参数/值对象、封装字段/集合、分解条件、用卫语句、替换更清晰的算法。
- **名字和函数要揭示意图**：坏名字阻碍理解时先改名再做深活。

## 坏味道清单（快速自查）
| 坏味道 | 典型修法 |
| --- | --- |
| 重复代码 | 提取函数/类，提升到公共处 |
| 过长函数 | 提取函数，按意图切块 |
| 过长参数列表 | 引入参数对象/保持对象完整 |
| 发散式变化 | 按变化原因拆类 |
| 霰弹式修改 | 把散落的改动内聚到一处 |
| 依恋情结 | 把方法移到它依赖的数据旁 |
| 基本类型偏执 | 用值对象/类替换裸类型 |
| 重复条件 | 用多态/表驱动替换 |
| 临时字段 | 提取类，把临时字段和用它的方法放一起 |
| 中间人 | 移除中间人，直接调用 |
| 投机性泛化 | 内联无用抽象，删死代码 |
| 过长switch | 用多态替换条件逻辑 |
| 平行继承体系 | 合并/消除一组 |
| 夸夸其谈未来性 | 删掉为"以后可能用"写的代码 |
| 注释掉的代码 | 直接删，git 里有历史 |
| 神秘命名 | 改名，让名字说意图 |
| 全局数据 | 封装成访问函数/参数传递 |
| 循环引用 | 拆依赖方向，单向化 |
| 数据泥团 | 提取成类/记录 |
| 被拒绝的馈赠 | 用委托替换继承 |

## 小步重构手法（按需选）
rename / extract function / extract variable / inline / move statement / move function / split loop / replace loop with pipeline / introduce parameter object / encapsulate variable / decompose conditional / replace conditional with guard clause / replace magic number with constant / replace error code with exception / remove dead code

## 验证纪律
- 每步重构后跑测试（安全网），红了就回退上一步。
- 行为变更与结构变更分两个 commit，便于 review 和回滚。
- 重构结束 diff 应只含结构变化，不含行为变化。

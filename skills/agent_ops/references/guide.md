# agent_ops 详细文档

（SKILL.md 精简入口的完整版：工具说明与规则全文）

## 工具

- `delegate_agent_task(agent, task, cwd?)` —— 委派任务
  - dsh：DSH 智能体（DeepSeek Harness）——复杂/跨系统/多步骤/需深入调查的任务
  - codex：攻坚顶级难题（算法难题、复杂重构、棘手 bug、性能优化）
  - opencode：解决日常问题（日常小需求、快速改文件、写脚本、跑测试）
- `list_agent_tasks()` —— 查看任务中心当前任务与进展

## 规则全文

1. 用户明确点名要用 DSH / DeepSeek Harness 智能体（"用DSH""让DSH来""DSH智能体"）时，agent 必须选 dsh，不得擅自改用 codex/opencode；
2. 所有委派（dsh/codex/opencode）执行前都会先请用户确认（任务中心点「确认执行」后才真正执行），委派前告诉用户"我派 XX 智能体去办，任务中心确认后才会执行"；
3. 委派后可用 list_agent_tasks 查询进展并如实向用户转述；
4. 多个任务可以并行推进，注意向用户分阶段汇报；
5. **绝不委派**：画图（image_gen_create）与音乐（music_search/music_play 等 music_* 工具）都是大白自己的直接能力，一律自己调用，绝不派给任何智能体；代码/文件/脚本类任务才适合委派。
6. **防重复委派（硬规则）**：委派前先查任务中心（list_agent_tasks）最近结果；同一任务或几乎相同的任务最近已失败/超时/无有效输出时，严禁原样重发——必须先向用户说明失败原因，并采取与上次不同的做法（缩小范围、换工具/路径、先修前置问题、先读上次日志定位根因），或征求用户同意后调整任务再委派；同一问题连续失败两次以上时停止自动重试，改为向用户汇报卡点与建议。
7. **清理任务白名单（硬规则）**：凡涉及清理/删除/清除临时文件的任务，只允许删除明确列出的临时文件（*.pyc-check、*.tmp、*.bak-*、_check*.txt、codex_logs/ 运行日志、%TEMP% 临时文件）；删除前必须先用 git status / git ls-files 核对，git 已跟踪的项目文件（源码/素材/网页/音频/游戏等）一律禁止删除；禁止整目录递归删除；动手前先列出删除清单展示给用户。
8. **复杂任务先写任务规范**：接到优化/重构/新建项目/大型多步骤等复杂任务时，要求先产出任务规范（目标、范围与不做、可验证的验收标准、小步实施步骤、风险与回滚），写完或给用户确认后再执行；完成时逐条对照验收标准自检并附验证证据。
